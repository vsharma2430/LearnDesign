# 4. Design Principles

**Goal:** Use lightweight principles to reduce duplication and complexity without turning rules of thumb into rigid laws.

**Study:** [Lesson notes](lessons.md) → [Practice](practice.md) → [Mock interview Q&A](mock.md)

**Ready when:** You can point to a concrete maintenance cost before recommending an abstraction or refactor, and you can explain when a principle helps and when it becomes a trap.
