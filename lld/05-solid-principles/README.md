# 5. SOLID Principles

**Goal:** Recognize designs that are difficult to change because responsibilities, contracts, and dependency direction are poorly shaped.

**Study:** [Lesson notes](lessons.md) → [Practice](practice.md) → [Mock interview Q&A](mock.md)

**Ready when:** You can apply each principle to a concrete change scenario, explain the trade-off behind the design, and identify when a proposed abstraction is excessive.

## Topics

- Single Responsibility Principle (SRP)
- Open/Closed Principle (OCP)
- Liskov Substitution Principle (LSP)
- Interface Segregation Principle (ISP)
- Dependency Inversion Principle (DIP)

These principles are best used as design judgment tools, not as rigid dogma. The question is always: does this boundary reduce change cost without creating unnecessary complexity?
