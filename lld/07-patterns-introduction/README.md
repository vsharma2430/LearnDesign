# 7. Design Patterns Introduction

**Goal:** Treat patterns as reusable design vocabulary, not mandatory templates.

**Study:** [Lesson notes](lessons.md) → [Practice Q&A](practice.md) → [Mock interview Q&A](mock.md)

**Ready when:** You can identify a concrete design pressure, explain how a pattern addresses it, describe its cost, and defend a simpler alternative when no pattern is needed.
